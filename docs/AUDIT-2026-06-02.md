## A. Engine continuity (initial work)

### A1. Agent stops after "好" + one tool call · FIXED

The flagship bug that triggered this audit. After one tool call the model
would return an empty response and the engine would mark the turn complete
with no follow-up. Three layers of fix landed before the audit started:

1. `src/core/QueryEngine.ts` — empty-after-tool nudge with bounded retry.
2. `src/services/prompt/defaultTemplate.ts` — "Multi-Step Execution
   Discipline (CRITICAL)" section in the base rules.
3. `src-tauri/src/claude/http/request_builder.rs::format_messages_for_openai`
   — preserve assistant `content` when `tool_calls` are also present.

Test coverage added in `src/core/__tests__/QueryEngine.test.ts`.

See memory: `agent-loop-continuity.md`.

## B. State / session-isolation (chat store)

### B1. `stopGeneration` cancels the wrong session after a fast switch · FIXED

`stopGeneration` was reading `get().currentSessionId` (what the user is
VIEWING right now) instead of the session whose engine is actually
streaming. After Session A starts a turn → user switches to B → user clicks
Stop, Session B got cancelled and Session A's engine kept running forever,
leaking tokens and corrupting B's last assistant message with A's tail
tokens.

Fix: introduced a module-scope `activeStreamingSessionId` that `sendMessage`
sets via `markStreamingSessionActive(activeSessionId)` when streaming begins
and clears via `clearStreamingSessionActive(activeSessionId)` in its
`finally` blocks. `stopGeneration` now prefers
`activeStreamingSessionId ?? currentSessionId`.

File: `src/store/chat/chatActions.ts`

### B2. `updateLastMessage` writes to whichever session is currently viewed · FIXED

`updateLastMessage` now accepts an optional `targetSessionId` parameter
(`src/types/chat.ts` + `src/store/chat/chatActions.ts`). Falls back to
`currentSessionId` for legacy callers. All long-running sites in
`sendMessage`, `stopGeneration`, `generateBrowserResultResponse`, and
their error-path siblings now pass their captured `activeSessionId` /
`pinnedSessionId`, so post-await mutations land on the session that owns
the work rather than whatever the user is now viewing.

### B3. `generateBrowserResultResponse` commits to current session · FIXED

Now captures `pinnedSessionId = currentSessionId` at start and threads it
through `updateLastMessage` on both the success and error paths.

### B4. Streaming timeout doesn't break the for-await loop · FIXED

`runChatTurn` now accepts a `signal: AbortSignal` via `RunChatTurnOptions`
and checks it before each API call AND inside the inner stream loop. When
signaled, the engine yields an `error` event with a new
`RunChatTurnAbortedError` and returns immediately. The streaming-timeout
path in `chatActions.ts` now creates an `AbortController`, passes its
signal into `runChatTurn`, and calls `controller.abort(...)` when the
timeout fires — so the engine actually exits instead of draining
naturally. Same controller is also fired from `stopGeneration`
(`abortActiveStreaming(targetSessionId, ...)`) and from `selectSession`
when switching away from a streaming session.

Files: `src/core/QueryEngine.ts`, `src/store/chat/chatActions.ts`,
`src/store/chat/streamingAbort.ts` (new), `src/store/createChatStore.ts`

### B5. `selectSession` resets streaming state while engine is running · FIXED

`selectSession` now calls `abortActiveStreaming(previousSessionId, ...)`
BEFORE issuing `stop_subprocess` and resetting streaming state. The
engine sees the abort signal immediately (via B4) and exits its
for-await loop, so the leftover engine no longer corrupts the new
session's last message.

File: `src/store/createChatStore.ts`

### B6. `selectSession` not awaited before `addMessage` · FIXED

`sendMessage` now uses `get().addMessageToSession(activeSessionId, ...)`
for the user message AND the assistant placeholder, instead of the
session-implicit `addMessage(...)`. Same for the browser-result follow-up
path (uses `pinnedSessionId`). The pinned session is captured before
any await, so concurrent clicks can't redirect the message to a
different session.

File: `src/store/chat/chatActions.ts`

### B7. Tool-call metadata never written back to the persisted assistant message · FIXED

`updateLastMessage` now accepts an optional `toolCalls` parameter; the
sendMessage turn collects every `tool_batch_request.tools` chunk into
`accumulatedToolCalls` and passes them at turn end. `messageToDb`
already round-trips `tool_calls`, so a reload now produces the same
history the engine had — `buildApiMessages` no longer needs to drop
assistant blocks with missing tool_use → tool_result pairs.

Files: `src/types/chat.ts`, `src/store/chat/chatActions.ts`

## C. IPC / Rust-TS boundary

### C1. `execute_with_context` double-validates and breaks approval tokens · FIXED

Refactored to call a new `execute_with_validated_entry(req, entry, args)`
helper that dispatches the tool handler directly, skipping the redundant
re-validation that was consuming approval tokens against a session-less
context.

File: `src-tauri/src/tools/registry.rs`

### C2. `execute_single_tool` Tauri command passed None for session_id · FIXED

Now takes an optional `sessionId` parameter and forwards it.

File: `src-tauri/src/commands/tools.rs`

### C3. Frontend `execute_single_tool` invoke missing `sessionId` · FIXED

Both `chatToolExecution.ts` invocation paths (`execute_single_tool` +
`execute_tool`) now forward `sessionId`, `approvalToken`, and
`executionId`.

File: `src/store/chat/chatToolExecution.ts`

### C4. SSE line buffer unbounded — OOM risk · FIXED

`stream_response` accumulated bytes into a `Vec<u8>` until it found `\n`.
Added a 16 MiB cap with an `AppError::ProcessError` if exceeded.

File: `src-tauri/src/claude/stream_parser.rs`

### C5. Cancellation returns `Ok(empty_response())` not an error · FIXED

Added a `ClaudeHttpError::Cancelled` variant that is non-retryable and
maps to `AppError::ProcessError("Request cancelled by user")`. The
`tokio::select!` in `executor.rs` now returns
`Err(ClaudeHttpError::Cancelled)` instead of `Ok(empty_response())`, so
the frontend gets a distinct error event instead of a phantom successful
empty turn. `empty_response()` is retained as a utility constructor for
tests / future placeholder use.

Files: `src-tauri/src/claude/http/error_mapping.rs`,
`src-tauri/src/claude/http/executor.rs`

### C6. `format_messages_for_anthropic` silently drops malformed tool_result · FIXED

When `extract_tool_result` returns `(None, None)` we now synthesise a
placeholder `tool_result` with `is_error: true` and a clear message
("envelope was malformed and could not be parsed") so the previous turn's
`tool_use` block is never left dangling. Also logs to stderr for
diagnosis.

File: `src-tauri/src/claude/http/request_builder.rs`

### C7. DeepSeek `supports_tool_calls` defined as `!supports_reasoning` · FIXED

Introduced `deepseek_model_supports_tool_calls(model_lower)` with a
positive allowlist (`deepseek-chat`, `deepseek-coder`, `deepseek-vl`,
`deepseek-v[2-5]-chat`). Reasoner / R1 models still correctly excluded.
Test extended to assert that `deepseek-v4-chat` IS tool-capable — a
regression guard against the old `!is_reasoning` logic.

File: `src-tauri/src/claude/provider.rs`

### C8. Retry policy ignores `Retry-After` header · FIXED

Added `next_retry_delay_with_hint(attempt, policy, error)` that takes
the server's `Retry-After` and the exponential backoff, picks the larger
of the two, and clamps by `max_delay_ms * 4` so a pathological
`Retry-After: 3600` from a buggy upstream can't freeze the client. Four
new unit tests cover all paths.

File: `src-tauri/src/claude/http/retry.rs`

## D. Tool execution & permission flow

### D1. Approval token + executionId lost on legacy `execute_tool` path · FIXED

TS side patched (chatToolExecution.ts forwards both). Rust legacy
handler now accepts and forwards them too — see D7.

### D2. Duplicate `tool_call_id` silently overwrote earlier results · FIXED

Duplicates detected in `StreamingToolExecutor.executeBatch`; the result
is replaced with a structured error explaining the collision; the
duplicate set is summarised in a console warn.

File: `src/services/StreamingToolExecutor.ts`

### D3. preToolUseHooks run twice for concurrent tools · FIXED

`ToolExecutionOptions` now has a `skipPreHooks?: boolean` flag. The chat
layer (which already runs `runPreToolUseHooks` per request in
`executeConcurrentTools`) now passes `skipPreHooks: true` when calling
`executeBatch`, so the second always-on hook pass that was clobbering
`modifiedArgs` and double-counting classifier metrics is gone.

Files: `src/services/StreamingToolExecutor.ts`,
`src/store/chat/chatToolExecution.ts`

### D4. `Skill` tool malformed-args parse error silently swallowed · FIXED

`chatToolExecution.ts:842-859` now surfaces malformed Skill arguments via
`uiStore.addNotification('error', ...)` so the mismatch between "what the
LLM intended" and "what activeSkill says" is visible to the user.

### D5. workDir snapshot in batch is stale after mid-batch session mutation · FIXED

`handleToolBatchRequest` now re-reads `session.workDir` from `get()`
right before each serial tool invocation, falling back to the original
snapshot only when the session is gone.

File: `src/store/chat/chatToolExecution.ts`

### D6. Permission ledger records only "debated" tools · FIXED

Added `recordPermissionDecision(entry)` to `useUIStore` as the single
chokepoint. The decision enum on `PermissionLedgerEntry` now includes
`auto_approved` and `allowed_by_backend`. `chatToolExecution.ts`
calls it from the `canAutoApproveTool` branch and the
`preview.decision === 'allowed'` branch, so the ledger now records
every decision the system makes on the user's behalf — not just the
ones that hit the prompt.

Files: `src/types/ui.ts`, `src/store/uiStore.ts`,
`src/store/chat/chatToolExecution.ts`

### D7. executionId reached `execute_tool` legacy path (Rust half) · FIXED

`execute_tool` in `commands/chat.rs` now accepts `executionId` and the
`execute_command` arm threads it (preferring the value embedded in the
tool args, set by `prepareCancellableToolArgs`, over the top-level Tauri
arg) into `execute_bash_for_tool`. Cancel-the-process is no longer a
no-op for tools that flow through this command.

File: `src-tauri/src/commands/chat.rs`

### D8. Prevalidated vs native result race on same id · FIXED (by D2)

Subsumed by the duplicate-id detection in D2.

## E. Resource lifecycle (listeners / timers / handles)

### E1. `useClipboard` timers leak after unmount · FIXED

`useRef` for the timer id, `mountedRef` for unmount gate, clear-and-schedule
helper. No more setState-on-unmounted warnings.

File: `src/hooks/useClipboard.ts`

### E2. `FileDropOverlay` listen-then-unmount race · FIXED

`cancelled` ref guards the three `.then(collect)` handlers; if a listen
resolves after cleanup, the unlisten is invoked immediately so the
listener never reaches the array.

File: `src/components/FileDropOverlay.tsx`

### E3. `WorkflowOutputPanel` stream callback never cleared · FIXED

`useEffect` returns a cleanup that sets the callback to `null`. The
engine's setter signature was widened to accept `StreamChunkCallback | null`.

Files: `src/components/workflow/WorkflowOutputPanel.tsx`,
`src/services/workflowEngine/engine.ts`

### E4. `runDelegationPlan` timeout timer not cleared on early completion · FIXED

Timeout id captured into `timeoutId`; cleared on whichever side of the
`Promise.race` wins. No more `forceFinish` firing on already-completed
plans.

File: `src/services/orchestration/runDelegationPlan.ts`

### E5. `ChatMessage` `ReasoningBody` copy-feedback timer leak · FIXED

Ref-based timer + mountedRef gate, mirroring E1.

File: `src/components/ChatMessage.tsx`

### E6. `BrowserMiniPreview` / `BrowserCompactSummary` copy-feedback timer leak · FIXED

Both components now use a ref-based timer + `scheduleCopyLogsReset()`
helper that clears any prior id before scheduling a new one, with a
cleanup in useEffect.

Files: `src/components/BrowserMiniPreview.tsx`,
`src/components/BrowserCompactSummary.tsx`

### E7. MCP stdio transport stderr task not always aborted on Drop · FIXED

`StdioTransport::Drop` now `abort()`s the stderr-draining JoinHandle
BEFORE killing the child process. The previous order (kill → abort)
had a small window where the task could still observe pipe bytes
between `start_kill` and `abort` and write a final log line that
referenced a process the rest of the app already considered gone.

File: `src-tauri/src/mcp/transport/stdio.rs`

### E8. `StreamingToolExecutor` race watchdog timer not cleared · FIXED

Captured `watchdogId` in a `let` outside the `Promise.race`; cleared
via `.finally()` on the IPC promise. Closure no longer outlives the
batch.

File: `src/services/StreamingToolExecutor.ts`

## F. Silent error paths

### F1. `executeFrontendOnlyBatch.catch` discards `error_kind` · FIXED

Routes through `buildStructuredToolError` so `error_kind` survives into
telemetry / the tool budget classifier / the model's view of the failure.

File: `src/services/StreamingToolExecutor.ts`

### F2. `writeClipboardText().catch(() => undefined)` in AutoResearch · FIXED

Both clipboard handlers (`handleCopyLiveOutput`, `handleCopyAllEvents`)
now surface failures via `showLiveOutputFeedback('copy_failed')` and log
to console. New i18n key `autoresearch.liveOutput.copyFailed` added in
both en-US and zh-CN. User no longer thinks copied content is on the
clipboard when it isn't.

Files: `src/components/AutoResearchPanel.tsx`,
`src/i18n/types.ts`, `src/i18n/locales/en-US.ts`, `src/i18n/locales/zh-CN.ts`

### F3. AutoResearch Telegram notifier has no fallback channel · FIXED

The notifier now exposes `getLastDelivery()` (per-instance) AND a
module-scope `getLastNotifierDelivery()` + `subscribeNotifierDelivery()`
that any UI component can subscribe to without threading the notifier
through props. `AutoResearchPanel` now renders a status banner at the
top of the panel when the most recent delivery failed or the notifier
is disabled — the user can no longer assume notifications are working
when they aren't.

Files: `src/services/autoresearch/notifier.ts`,
`src/services/autoresearch/index.ts`,
`src/components/AutoResearchPanel.tsx`

### F4. `TerminalPanel` invoke `.catch(() => {})` on input/resize · FIXED

The first IPC failure flips the panel to `error` state with an
`errorMessage` describing the desync so the user knows the panel is
broken before assuming their keystrokes ran.

File: `src/components/TerminalPanel.tsx`

### F5. `BrowserSurfaceViewport` sync errors swallowed · FIXED

All three `.catch(() => {})` sites (`moveBrowserSurface` and two
`setEmbeddedSurfaceVisibility(false)` calls) now log to console with
context AND the `moveBrowserSurface` path posts a throttled (5 s)
in-app notification so the user sees "overlay positioning failed —
clicks may land in the wrong place" instead of silently mis-clicking.

File: `src/components/BrowserSurfaceViewport.tsx`

### F6. Native browser overlay inject/remove errors silently dropped · FIXED

Both `injectOverlay` and `removeOverlay` now log on failure AND the
inject path posts a throttled (5 s) in-app warning notification so a
user whose page navigated mid-overlay learns about it instead of
waiting for a click that will never arrive.

File: `src/utils/nativeBrowserAgent.ts`

### F7. Database migration `ALTER` failures silently ignored · FIXED

Introduced `execute_idempotent_migration(conn, sql, label)` that
recognises benign "duplicate column" / "already exists" errors and
propagates everything else. All `let _ = conn.execute(...)` sites in
the migration switch are gone.

File: `src-tauri/src/database.rs`

### F8. AutoResearch notifier silent no-op on misconfig · FIXED

`createNotifier` now logs `[AutoResearch Notifier] disabled (...)` once
at construction so devtools shows whether notifications are wired up,
and every send failure includes the `chatId` so it can be mapped to the
operator's config. Combined with F3, consumers can also read the last
delivery status programmatically.

File: `src/services/autoresearch/notifier.ts`
